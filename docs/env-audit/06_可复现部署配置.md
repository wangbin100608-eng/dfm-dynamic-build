# 可复现部署配置

## A. 生产实例（保持现状，不建议改动）

```bash
docker run -itd --privileged --name redroid11 \
  -v /root/redroid-data11:/data \
  -v /root/盘点/libndk_translation.so:/system/lib64/libndk_translation.so:ro \
  -p 5555:5555 redroid/redroid:11.0.0-latest \
  androidboot.redroid_width=1080 androidboot.redroid_height=1920 androidboot.redroid_dpi=480
```

**注意**： patched 转译器 bind mount 已证实导致死循环（见 Native Bridge 报告 §4.5-4.6），建议去掉该 bind 恢复原生转译器。

## B. 独立测试实例（推荐，用于所有验证）

```bash
mkdir -p /root/redroid-x86-test-data
docker run -itd --privileged --name redroid-x86-test \
  -v /root/redroid-x86-test-data:/data \
  -p 5556:5555 redroid/redroid:11.0.0-latest \
  androidboot.redroid_width=1080 androidboot.redroid_height=1920 androidboot.redroid_dpi=480
```

特点：无自定义 SO bind，使用镜像原生 2021 转译器。

## C. 安装目标 APK

```bash
docker cp /root/三角洲/dfm-apk/dfm-official-1.201.37119.49.apk \
  redroid-x86-test:/data/local/tmp/dfm.apk
docker exec redroid-x86-test /system/bin/pm install -r /data/local/tmp/dfm.apk
```

## D. 启动与监控

```bash
# 启动（用 docker exec，不依赖 adb）
docker exec redroid-x86-test /system/bin/am start \
  -n com.tencent.tmgp.dfm/com.epicgames.ue4.SplashActivity

# 监控 Undefined instruction
docker exec redroid-x86-test /system/bin/logcat -v brief | grep 'Undefined instruction'

# 资源
docker stats redroid-x86-test --no-stream
```

## E. ADB 连接注意事项

- `adb root` 会把 adbd 改成 `--root_seclabel=u:r:su:s0`（见 `/proc/<adbd>/cmdline`），导致 host adb 长期离线，即使重启容器/重置 adb key 也未必恢复。
- **推荐全程用 `docker exec <container> /system/bin/<cmd>` 替代 adb**，避免此问题。
- 若必须用 adb：避免 `adb root`；容器首次启动后直接 `adb connect 127.0.0.1:5555`。

## F. 稳定性监控脚本

`stability_monitor.sh`（本目录）——每 30 秒采集 CPU/内存/PID/状态/错误计数，输出 CSV + log，60 次共 30 分钟。

## G. 前置条件

- Docker 29.1.3+，privileged 容器
- 内核已加载：`binder_linux`, `ashmem_linux`, `vkms`（后者仅 Waydroid 实验用）
- 无 KVM、无物理 GPU（本配置不依赖二者）
