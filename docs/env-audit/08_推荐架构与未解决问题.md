# 推荐最终架构 与 尚未解决的问题

## 推荐最终架构

### 结论先行

**本机（无 KVM、无物理 GPU、x86_64）无法稳定运行目标游戏 APP《三角洲行动》国服（纯 arm64 native）。** 推荐架构分两层：

### A. 平台层（已验证稳定，可交付）

```
宿主机 Ubuntu 22.04 / x86_64 / 内核 5.15
  └─ Docker 29.1.3 (privileged, overlayfs, systemd cgroup)
       └─ Redroid 11.0.0 (amd64)
            ├─ BinderFS (binder/hwbinder/vndbinder) ✓
            ├─ ashmem ✓
            ├─ SwiftShader EGL (OpenGL ES 3.2) ✓
            └─ 原生 x86_64 应用：可稳定运行
```

这一层是**稳定的**，可用于普通 x86_64 Android APP 测试，不依赖 KVM/GPU。

### B. 目标 APP 层（本机不可行，推荐外部方案）

```
目标 APK 纯 arm64-v8a（90 个 so，核心 libUE4.so 561MB）
  └─ 必须 ARM64→x86_64 二进制翻译
       └─ Native Bridge (libndk_translation) 
            ├─ 原生 2021 版：报 1 次 Undefined instruction 后停住（不推进）
            └─ patched 版：同一指令死循环（已证实是被 NOP patch 破坏）
  → 本机结论：无论哪个版本都无法让 APP 进入游戏
```

**推荐最终架构**：

| 场景 | 推荐方案 |
|---|---|
| 运行目标游戏、抓游戏内网络包 | **root arm64 真机**（唯一可靠）；x86_64 转译不可用 |
| 静态/CPU 动态分析 | 本机 Unicorn 指令级模拟（`dfm-dynamic-build/tools/emu/`），不依赖 Android |
| 普通 x86_64 Android APP 测试 | 本机 Redroid + SwiftShader（平台层稳定） |
| 生产 redroid11 转译器 | **去掉 patched SO 的 bind mount**，恢复镜像原生版（避免死循环） |

### 不推荐

- 继续在 x86_64 上 patch 转译器/堆叠兼容层：已证实 11 字节 patch 引入死循环，收益为负。
- Waydroid + 软件渲染替代：SurfaceFlinger present 死锁（另见总报告）。
- 把 EGL 正常当作 APP 兼容：任务2 已反证（EGL 正常但 APP 纯 arm64 无法运行）。

## 尚未解决的问题

1. **原生 2021 转译器为何停在 PermissionActivity**：报 1 次 Undefined instruction 后进程存活但不推进，主线程状态需进一步确认（可能在等某个 native 回调）。本次 30 分钟测试未观察到恢复。
2. **运行时代码 `0x5ea1b801` 的来源**：该指令不在 libUE4.so 静态内容中，是运行时 JIT/解密生成。具体生成路径（UE4 脚本 VM / ACE 保护 / LuaJIT）未定位。
3. **patched 转译器的来源与意图**：`/root/盘点/libndk_translation.so` 的两处 NOP patch（InitInterpreter CALL、Umaal JNE）由谁/为何打入无记录；建议追溯或废弃。
4. **30 分钟稳定性测试的完整性**：首次监控因脚本字段换行瑕疵只采到 4 点；已用 setsid 重启完整监控，最终结果见 `stability-30min.csv`（若采样未满 60 次需在交付时说明）。
5. **真机路径未实测**：root arm64 真机上的 Frida 抓包（四把钥匙）本环境无设备，未执行。
6. **split APK 场景**：本次目标为单 APK；若未来目标为 split APK，需扩展任务2 的检查流程。
