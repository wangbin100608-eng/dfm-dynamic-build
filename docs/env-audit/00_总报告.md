# Android x86_64 无 KVM / 无 GPU 兼容性专项 — 总报告

- 时间：2026-11-28（UTC）
- 目标：在不依赖 KVM 和物理 GPU 前提下，建立稳定 Android x86_64 环境；评估目标 APP《三角洲行动》国服运行可行性
- 原则遵守：所有结论有实测证据；**未将 EGL 正常直接认定为 APP 兼容性正常**

## 一句话结论

**平台层稳定可交付（Docker+Redroid+SwiftShader，Binder/ashmem/EGL 全正常），但目标 APP 是纯 arm64 native，在本机 x86_64 上走 Native Bridge 不可行：原生转译器报未定义指令后停住，patched 转译器在同一指令死循环。根因已定位为生产实例挂载的转译器被 11 字节 NOP patch 破坏。**

## 关键证据链（推翻多个先前假设）

1. **不是渲染问题**：EGL/SwiftShader/SurfaceFlinger 全程无错（任务3）。
2. **不是静态指令不支持**：`0x5ea1b801` 在 libUE4.so 中出现 **0 次**（运行时生成代码）。
3. **不是转译器原生缺陷，但原生版也失败**：原生 2021 转译器在独立实例只报 **1 次**错，随后目标进程触发 **`SIGILL (Fatal signal 4)`** 崩溃；生产实例（patched）报 **44,933 次/3秒**（死循环）。两版本都无法运行目标 APP，失败模式不同。
4. **根因是人为 patch**：两个转译器仅差 11 字节，两处均为 NOP 替换：
   - `InitInterpreter`: CALL → 5×NOP
   - `intrinsics::Umaal`: JNE → 6×NOP
   这两处破坏转译器逻辑，把"快速 SIGILL 崩溃"变成"永久死循环"。
5. **三实例因果闭环已验证**：patched（生产）= 死循环；原生（测试实例）= SIGILL；patched 新实例 = 死循环精确复现（同一错误地址低 12 位 `748`）。
5. **第一次 ANR 是另一回事**：JIT 翻译 561MB so 超时（ANR trace：`ExecuteGuest → munmap`），反复启动预热缓存后解决。
6. **adb root 的副作用**：把 adbd 改成 `--root_seclabel=u:r:su:s0`，host adb 永久 offline；全程改用 `docker exec` 解决。
