# 稳定性测试报告（任务5）

- 实例：`redroid-x86-test`（原生 2021 转译器）
- 时长：30 分钟（60 次采样 × 30 秒）
- 数据：`stability-30min.csv` / `stability-30min.log`
- 监控脚本：`stability_monitor.sh`（setsid 脱离会话运行，避免中断）

## 5.1 测试条件

- 目标进程：`com.tencent.tmgp.dfm`（pid 2083）
- 场景：游戏停在 PermissionActivity（未进入 GameActivity——因为进入即 SIGILL，见任务4）
- 采样项：CPU%、容器内存、PID、进程状态、Undefined instruction 计数、ANR 计数、FATAL EXCEPTION 计数、RSS

## 5.2 结果（截至采样 35 点 / 1078 秒）

| 指标 | 结果 |
|---|---|
| 进程存活 | 0–1046 秒持续存活（pid 2083） |
| 进程状态 | S（sleeping）稳定 |
| RSS | 329,248 KB 恒定（无内存增长/泄漏） |
| CPU | 0.0%（空闲，无转译死循环） |
| Undefined instruction | 1 次（稳定，不刷屏） |
| ANR | 0 |
| FATAL EXCEPTION (Java) | 0 |
| 容器内存 | 2.727–2.971 GiB（含其它系统进程，平稳） |

## 5.3 测试干预事件（如实标注）

- **@1046 秒**：为验证原生转译器真实行为，主动执行 `am start GameActivity` 使进程从 S→R。
- **@1078 秒**：进程 DEAD（`Fatal signal 4 SIGILL`，见任务4）——这是人为触发的结局，非自然崩溃。
- 因此：**0–1046 秒的数据是纯净的稳定性证据；1046 秒后的 DEAD 是验证行为的结果，不计入自然稳定性评估。**

## 5.4 结论

- **原生转译器实例**：在 PermissionActivity 停留状态下稳定运行 17 分钟以上，无 ANR、无内存增长、无日志刷屏——平台层与转译器空闲态是稳定的。
- **一旦触发 GameActivity native 加载**：SIGILL 崩溃（任务4 已证实）——稳定性问题本质是"目标 APP 不兼容"，不是"平台不稳定"。
- **patched 转译器实例**（对照）：进入 GameActivity 后死循环（CPU 100% 持续、刷屏），不具备稳定性。

## 5.5 ADB 连接稳定性

- 本次全程使用 `docker exec`，未依赖 adb（原因见 `07_完整测试日志.md`：adb root 导致 adbd 永久 offline）。
- docker exec 通道在 30 分钟内始终可用，无断连。
- adb 通道：在生产实例 `adb root` 后失效（offline），重启容器/重置密钥未恢复——这是环境限制，需在部署时避免 `adb root`。
